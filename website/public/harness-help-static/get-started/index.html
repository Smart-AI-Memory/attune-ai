Install Harness¶

Install uv if needed. Harness requires Python 3.12 or later.

uv tool install --python 3.12 attune-harness

Check a local result¶

attune-harness

Look for "status": "verified". The demo runs locally and needs no API key.

Connect your assistant¶

  • Set up Codex, then invoke $attune-harness.
  • Set up Claude Code.

Set up the practice folder¶

Build and check an HTML report from six sample activity entries. You can preview the sample report. The six lessons use one local project and need no API key.

  1. Download practice ZIP and extract it into a new folder.
  2. Open a terminal in the extracted folder that contains practice.py. Use Bash or Zsh on macOS or Linux. Install Git if needed.
  3. Run these commands to set up a separate environment with Harness and pytest.
COURSE_WORK="$(pwd -P)" &&
uv venv --python 3.12 .venv &&
uv pip install --python .venv/bin/python -r requirements-practice.txt &&
. .venv/bin/activate

If you already have a separate practice environment with Harness and pytest, activate it and run COURSE_WORK="$(pwd -P)" from the extracted folder. See the tested versions and results.

Keep this terminal open for lesson 2. You can run the rest of the exercise offline.

Choose goal-driven development¶

Read How people and AI work together to understand your decisions and the AI's role in carrying out accepted work.

Start with a small outcome in a project you know. Ask your assistant to help prepare the plan for your review.

Example prompt

Use Harness to help me plan an update to this project. Help me define the goal, affected files and checks before we build.

Use Plan a change to prepare your request. Browse all goals to find a guide for review, repair, testing, or saved work.

Review the proposed scope, participants, and checks before accepting the plan. Authorize the build when you are ready to start it.

Tip Use status to inspect saved decisions before continuing.

Choose spec-driven development¶

Use a specification when the work needs more structure than a short request. Follow Create a spec with roundtable help for an existing worked example and review points. The worksheet records proposed wording; copying a prompt or preparing a draft does not dispatch a model, approve the spec or start implementation.

A reviewed spec still needs a supported, accepted plan before a build can start. The plan-and-build guide explains that procedure. If you already have a supported Markdown plan, follow the plan import instructions and review the imported scope before acceptance.

Keep a working setup¶

  • If you already use Harness, check the update in a separate environment before switching. See the migration guide for saved tasks, memory, and host settings.
  • If your shell can't find the command, add the uv tool directory to your path. See the installation guide for pipx and virtual environments.
  • Check the supported Windows configurations and optional integrations if you need them.
