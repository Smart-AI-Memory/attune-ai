# Discovery-Sweep Rich Surface — requirements

The "double-fit showcase": wire the working `show_widget` rich surface
(shipped in `elicitation-form-surface` D11) into discovery-sweep on
*both* sides — a rich **input** scoping form and a rich **output**
triage board — because discovery-sweep is the one flow that is a genuine
fit on both (per `elicitation-form-surface` D12).

## Grounding (verified against code, not docstrings)

- `cli_workflow.default_sources()` returns **7** real sources
  (`pattern-scan` non-LLM, + `bug-predict`, `security-audit`,
  `dependency-check`, `perf-audit`, `doc-audit`, `test-audit` LLM).
  "Phase 2B complete" — they all run.
- **Stale docstrings:** `workflow.py`'s module docstring and
  `sources/__init__.py` still say "Phase 1 ships only PatternScanSource"
  — wrong, and nearly mis-scoped this work. Fix them (FR-4).
- The engine already filters by a SINGLE `source` name
  (`workflow.py:542`); there is no plural filter and the MCP tool
  (`path` / `budget_usd` / `no_llm`) exposes none.
- Output is `SweepResult{queue, questions, rejected, metadata}`,
  serialized via `dataclasses.asdict`. `Finding` carries
  `source, severity, title, description, file, line, confidence, tags`.

## Functional requirements

- **FR-1 (output board).** The `discovery_sweep` tool emits a
  `board_html` field: the `queue/questions/rejected` buckets rendered as
  a three-column triage board (severity-colored queue cards with
  `file:line` + source + confidence; questions with `reason`/`next_step`;
  rejected collapsed to a count + rule summary; footer = spend/budget,
  sources ran, failures, duration). Pass `board_html` to
  `mcp__visualize__show_widget`. Generated by a pure, injection-safe
  helper (`html.escape`, CDS tokens, transparent bg, no `position:fixed`).
- **FR-2 (input form).** The discovery-sweep skill renders a scoping
  form via the widget surface: `path` (text), **audits** (multi-select
  over the 7 source names, default all), `mode` (pattern-only vs include
  LLM), `budget` (number, shown when LLM included). AskUserQuestion
  fallback. *(Phase 2 — needs FR-3.)*
- **FR-3 (sources param).** The `discovery_sweep` tool + run path accept
  `sources: list[str]` filtering `default_sources()` by name; unknown
  names are an error (R4-style), not silently dropped. Default = all 7.
  *(Phase 2.)*
- **FR-4 (doc-fiction fix).** Correct the stale "1 source" docstrings to
  reflect the live 7-source registry.

## Non-goals

- No new MCP tool (would bump the 47-count guarded by
  `test_website_version_accuracy::TestCapabilityCountsSync` + README +
  `features.ts`). Extend the existing tool's response instead.
- No new source adapters; no change to triage/dedup logic.
- `slider`/`color` widget controls stay deferred (elicitation D11).

## Build order

1. **Phase 1 (this spec's first PR):** FR-1 board helper + tool
   `board_html` + skill output wiring + FR-4 docstring fix + tests.
2. **Phase 2 (follow-up PR):** FR-3 `sources` param + FR-2 input form.

The output board is the visible showcase and carries no engine risk;
the input form needs the `sources` param to be honest (selecting an
audit must actually filter it — no fiction).

## Acceptance

- `discovery_sweep` result includes valid `board_html`; `show_widget`
  renders the three buckets + footer; no raw findings text interpolated
  into executable JS.
- Helper unit-tested (empty buckets, all-severities, missing
  file/line, injection attempt escaped).
- Stale docstrings gone; `default_sources()` count test stays green.
