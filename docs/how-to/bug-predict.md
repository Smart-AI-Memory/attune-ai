# How to Run Bug Prediction

Use this guide when you want to scan a file or directory for likely bug locations — before a merge, during code review, or as a periodic health check on high-churn modules.

## Quick start

Run a scan directly from your Claude Code conversation:

```
/bug-predict src/
```

You'll get a risk report grouped by severity with file paths, line numbers, and plain-English descriptions:

```
Bug Prediction Report
Risk Score: 73/100 | Files: 34 | Findings: 8

HIGH (2 findings)
  src/hooks/executor.py:89   dangerous_eval  eval() on user input
  src/plugins/loader.py:142  dangerous_eval  exec() in plugin loader

MEDIUM (3 findings)
  src/api/webhook.py:67      broad_exception bare except: masks errors
  src/config.py:203          broad_exception except Exception without logging
  src/memory/store.py:88     broad_exception swallowed error in write path

LOW (3 findings)
  src/auth/session.py:45     incomplete_code TODO: add token rotation
  src/api/routes.py:112      incomplete_code FIXME: rate limiting
  src/cli_router.py:78       incomplete_code HACK: temporary workaround
```

File links are clickable — click any entry to jump directly to the flagged line.

## Choose what to scan

| Command | What it scans |
|---------|---------------|
| `/bug-predict src/auth.py` | One file |
| `/bug-predict src/` | A directory tree |
| `/bug-predict .` | The whole project |

You can also use natural language:

```
predict bugs in src/
where are bugs most likely in the workflows module?
find risky code in the auth package
```

If you don't specify a path, the skill prompts you to scope the scan before it runs. It defaults to `src/` if you skip the prompt.

## Core API

| Symbol | Purpose |
|--------|---------|
| `BugPredictionWorkflow` | SDK-native orchestrator; coordinates three subagents (`pattern-scanner`, `risk-correlator`, `prevention-advisor`) and returns a unified `WorkflowResult` |
| `format_bug_predict_report(result, input_data)` | Formats a raw workflow result dict into the human-readable severity report shown above |
| `main()` | CLI entry point; wraps `BugPredictionWorkflow` for command-line use |

## Integration patterns

### Run programmatically and format the output

```python
from bug_predict.workflow import BugPredictionWorkflow
from bug_predict.report import format_bug_predict_report

workflow = BugPredictionWorkflow()
result = workflow.execute(path="src/")
print(format_bug_predict_report(result, input_data={"path": "src/"}))
```

### Extend the system prompt for project-specific context

```python
workflow = BugPredictionWorkflow(
    system_prompt_suffix=(
        "This codebase uses a custom plugin loader. "
        "Treat exec() calls in plugin/loader.py as HIGH risk regardless of context."
    )
)
result = workflow.execute(path="src/")
```

Pass `system_prompt_suffix` to append project-specific instructions to the orchestrator prompt without replacing the built-in guidance.

## What to do after a scan

- **Fix HIGH findings first** — ask "fix the dangerous_eval in executor.py" for a guided remediation.
- **Generate regression tests** — ask "write tests for the flagged files" to lock in the fix.
- **Drill into one area** — run `/bug-predict src/auth/` for a tighter, focused scan.
- **Track trends** — run the scan weekly and compare risk scores to catch drift early.
