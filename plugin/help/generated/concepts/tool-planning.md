# Planning

## What

High-level development planning for new features, TDD
scaffolding, and architecture review. Guides you through
goal definition, scope decomposition, dependency mapping,
and produces a structured plan with tasks, acceptance
criteria, and risk flags.

## Why

Jumping straight to code without a plan leads to rework.
Planning forces you to think through edge cases, define
done, and identify blockers before writing a single line
-- when changes are cheapest.

## When to use

- Before starting a new feature or epic
- When designing a TDD approach for complex logic
- To review architecture decisions before committing
- When decomposing a large task into smaller deliverables

## What it produces

| Output | Description |
|--------|-------------|
| Feature spec | Goals, scope, non-goals, constraints |
| Task breakdown | Ordered tasks with effort estimates |
| TDD scaffold | Test-first structure with red/green/refactor |
| Architecture review | Component diagram, coupling analysis |
| Risk assessment | Blockers, unknowns, mitigation strategies |
