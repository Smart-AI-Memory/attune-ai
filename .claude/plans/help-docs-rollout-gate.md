# Spec: Help-Docs Single-Source Rollout Gate

**Created:** 2026-06-21
**Spec home:** [docs/specs/help-docs-single-source/](../../docs/specs/help-docs-single-source/)
**Design lock:** decisions.md **D11** (hub page / Variant 1) + **D12**
(mkdocs nav via `on_config` hook); playbook
[r7-rollout-playbook.md](../../docs/specs/help-docs-single-source/r7-rollout-playbook.md)

---

## Context

The single-source pilot projected two features (`spec-engine`, `models`)
from `content/features/<F>.md` masters into `.help` kinds + 3 docs pages.
The 2026-06-21 design session locked the **entry-point convention** so
the ~270-feature rollout never has to re-touch nav per feature:

- **D11** — every feature gets a thin, projector-emitted **hub page** at
  `docs/features/<F>.md`, **Variant 1 (hero callout + card grid)**.
  Hero "Start here" → tutorial when present, degrading to how-to →
  reference. Card grid links the feature's available docs pages.
- **D12** — the hub is the **single "Features" nav entry per feature**,
  generated by a zero-dependency mkdocs `on_config` hook; the blanket
  `architecture/` exclude is dropped.

This spec is the **gate**: build the hub-emit + nav hook and prove the
rendered chain on the two pilot features before any bulk projection.

## Problem

Projecting a third feature today yields **orphaned, hub-less pages** —
`docs/how-to/<F>.md` etc. build but are "not in nav," and
`docs/architecture/<F>.md` is excluded wholesale. There is no front
door and no discovery surface (projected pages carry zero cross-links).
The convention is decided but **unimplemented**.

## Goals

1. Projector emits a Variant-1 hub page per feature (attune-author).
2. A mkdocs `on_config` hook wires every hub into a "Features" nav
   section and drops the blanket `architecture/` exclude (attune-ai).
3. The two pilot features render correctly end-to-end —
   spec-engine (tutorial-hero branch), models (degraded how-to-hero
   branch) — with `mkdocs build` clean and no orphans.

## End state

- `python scripts/project_features.py spec-engine` (and `models`)
  additionally writes `docs/features/<F>.md`.
- `mkdocs build` is clean; a "Features" section lists both hubs; each
  hub's hero + cards point to real, building pages.
- D11/D12 follow-ups flip to **implemented**; the per-feature loop in
  r7-rollout-playbook.md is mechanical and bulk rollout is unblocked.

---

## Design refinements (resolved during spec authoring)

- **Hub cards = published docs pages only.** The site has how-to,
  architecture, reference per feature (D10/playbook) — **not** concept
  (an in-tool `.help` kind with no site page). The mockup's 4th
  "Concept" card was in-tool thinking; on the site the **architecture**
  card carries the mental-model/Overview. Site hub = hero + cards over
  {how-to, reference, architecture}.
- **Tutorial signal = `master.nav.mkdocs["tutorial"]`.** spec-engine's
  master declares it; models' does not. No filesystem probing needed
  (belt-and-suspenders: the hook/build will surface a dead link if the
  declared tutorial page is missing).
- **Hero target precedence:** tutorial → how-to → reference (first
  declared in `nav.mkdocs`). The hero kind is removed from the card
  grid so it is not listed twice.
- **Cross-repo boundary.** T1 lands in **attune-author** (projector) and
  needs a release (0.21.0) + pin bump before T2–T4 (attune-ai) can
  consume it. T1 executes in a session rooted in an attune-author
  worktree **branched off main (0.20.0+)** — NOT the stale
  `silly-goodall-3f7191` worktree (0.19.0). T2–T4 execute in the
  attune-ai worktree after the release.

## Sequencing

```text
T1 (attune-author, new session off main) → release 0.21.0
        ↓ (PyPI)
T2 (attune-ai, here) pin bump + re-project pilots
        ↓
T3 (attune-ai) nav hook + FEATURES migration + exclude cleanup
        ↓
T4 (attune-ai) validate + close follow-ups
```

T3's hook code is independent of T1/T2 and could be drafted in parallel,
but it can only be **validated** once the pilot hubs exist (T2). Keep the
T2 → T3 → T4 order for a clean build gate.

## Out of scope

- Authoring master files for the other 23 manifest features (the bulk
  loop — starts after this gate proves green).
- In-tool hub surface (ops dashboard / help_lookup leading with the
  tutorial) — carried open on the P6 follow-up.
- The finer-grained `maintenance: projected` per-kind contract (P3).
