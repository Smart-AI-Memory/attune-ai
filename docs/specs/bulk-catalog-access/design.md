# Bulk + Catalog Access — Design

Grounded in the shipped plugin skill format (`plugin/skills/bug-predict/
SKILL.md`) and the sync pipeline (`scripts/sync_agents_skills.py`:
`plugin/skills/` → `.agents/skills/`, stripping Claude-Code-only
frontmatter fields).

---

## Touch points

| Layer | File | Change |
|-------|------|--------|
| Skill | `plugin/skills/bulk/SKILL.md` | new (adapt from `.claude/skills/bulk`) |
| Skill | `plugin/skills/catalog/SKILL.md` | new (adapt from `.claude/skills/catalog`) |
| Mirror | `.agents/skills/{bulk,catalog}/SKILL.md` | generated by sync script |
| Tool (opt.) | `tool_schemas.py` + `server.py` | `list_capabilities` (only if chosen — D-CAT) |
| Tests | `test_sync_agents_skills.py`, `test_plugin_reference_validation.py` | pass after regen |

No engine code under `workflows/`, `wizards/`, or `orchestration/`.

---

## Skill frontmatter (shipped convention)

Match `bug-predict`: only fields the sync script allows survive to
`.agents/`. Keep `name`, `description` (triggers live here),
`argument-hint`. **Drop** the `.claude/skills` legacy fields
(`category`, `aliases`, `version`, the `question:` picker block) — they
are not part of the shipped convention and the sync script does not carry
them.

---

## 1. `bulk` skill

Backed by the existing `analyze_batch` MCP tool (50% batch cost).

```yaml
---
name: bulk
description: "Batch API processing for 50% cost savings on non-urgent
  bulk analysis. Triggers on: batch, bulk process, batch API, cheap
  bulk, process many, overnight analysis, 50% savings."
argument-hint: "<what to batch>"
---
```

Body (bug-predict shape): `help_lookup(topic="bulk", mode="preamble")`
preamble with fallback → scoping ("what tasks / how many?") → execution
(call `analyze_batch` with the `requests` array; note async up-to-24h) →
output (batch id, status, how to retrieve). Reference only
`analyze_batch`.

## 2. `catalog` skill

Registry-driven enumeration. **D-CAT decides the data path** (see
decisions). Two options:

- **D-CAT-a (recommended): thin `list_capabilities` MCP tool.** A
  read-only tool that returns `{workflows: list_workflows(), wizards:
  list_wizards(), tools: <dispatch keys>}`. Wiring mirrors any handler:
  schema in `get_utility_tools()`, `_run_list_capabilities` in
  `server.py`, dispatch entry. ~30 lines, no engine code, keeps Claude
  from shelling out and guarantees accuracy.
- **D-CAT-b: CLI-only.** The skill instructs `attune features` +
  `attune workflow` listing. No new code, but output is CLI-shaped and
  wizards aren't in the CLI today.

Skill body either way: preamble → "show all / filter by category" scoping
→ render the live lists as grouped tables (workflows, wizards, tools) with
one-line descriptions → point to the specific skill for each.

Relationship to `attune-hub`: hub = *routing* ("take me to the right
workflow"); catalog = *enumeration* ("show me everything"). Triggers must
not collide — catalog owns "list/browse/what can attune do/show all
capabilities"; hub keeps "where do I start/route me".

## 3. Sync

After authoring, run `python scripts/sync_agents_skills.py` to generate
`.agents/skills/{bulk,catalog}/SKILL.md`, then
`sync_agents_skills.py --check` (the CI gate) must pass. Commit both the
`plugin/` source and the `.agents/` mirror together.

## 4. Help topics (optional, additive)

The preamble calls `help_lookup(topic="bulk"|"catalog")`. Both skills
include a literal fallback blockquote, so missing help topics degrade
gracefully. Authoring real help topics is a nice-to-have follow-up, not
a blocker.

---

## Risks

- **R1 (low):** `catalog` trigger phrases shadow `attune-hub`.
  Mitigation: the explicit enumeration-vs-routing split above; the
  skill-sync / disambiguation guard covers it.
- **R2 (low):** authoring `list_capabilities` drifts toward "engine
  code". Mitigation: it is strictly read-only over existing registry
  functions; if review disagrees, fall back to D-CAT-b (CLI).
- **R3 (low):** forgetting to regenerate `.agents/` mirror →
  `test_sync_agents_skills` fails. Mitigation: the task runs `--check`
  as a validation gate.
