# Discovery-Sweep Rich Surface — decisions

## D1 — premise survived a double near-miss; verify `default_sources()`, not docstrings

**Date:** 2026-06-28 · **Status:** decided

Scoping the "double-fit" hit the exact "registered ≠ working / spec text
drifts from code" trap twice:

1. The `discovery_sweep` MCP tool *schema* advertises 7 sources but
   exposes no way to select among them — so the "which-audits
   multi-select" looked unbuildable without an engine change.
2. `workflow.py`'s module docstring + `sources/__init__.py` say "Phase 1
   ships only PatternScanSource" — which would make a 7-way multi-select
   pure fiction.

Reading the actual registry (`cli_workflow.default_sources()`) refuted
both: it returns **all 7** ("Phase 2B complete"). The docstrings are
stale. **Lesson reaffirmed:** verify the live registry function, never
the module docstring or the tool's marketing description. The stale
docstrings are fixed here (FR-4) so the next reader isn't misled.

## D2 — output board ships first; no new MCP tool

**Date:** 2026-06-28 · **Status:** decided

The triage board is the visible showcase and needs no engine change (the
tool already returns the buckets). It ships in Phase 1.

**No new MCP tool** for rendering. A `discovery_sweep_render_board` tool
would push the live tool count 47 → 48, breaking the count guard
(`TestCapabilityCountsSync`, shipped this week), the README, and
`features.ts` `CAPABILITIES.mcpTools` — a ripple disproportionate to the
feature. Instead the existing `discovery_sweep` response gains a
`board_html` field (always populated; cheap from the in-memory result).
The agent passes it to `mcp__visualize__show_widget`. Mirrors the
`elicitation_render_widget → show_widget` pattern without a new tool.

Board generated by a pure helper `sweep_to_board_html(result, message="")`
in `attune.workflows.discovery_sweep.board` — same injection-safety
contract as `form_to_widget_html` (D11): `html.escape` all finding text,
no data interpolated into executable JS, CDS-token styling, transparent
background, no `position:fixed`.

## D3 — input form is Phase 2, gated on a real `sources` filter

**Date:** 2026-06-28 · **Status:** decided

A which-audits multi-select must actually filter the run, or it's the
fiction D1 warns against. So the input form (FR-2) is gated on the
`sources: list[str]` param (FR-3) and lands in Phase 2. The form's other
dimensions (`path`, `mode`/`no_llm`, `budget`) are real today, but
without the audits multi-select the remaining open fields don't justify
a form over the existing AskUserQuestion scoping — so the whole input
surface waits for FR-3 rather than shipping a thin form now.
