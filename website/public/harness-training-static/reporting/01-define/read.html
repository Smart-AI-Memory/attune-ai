  • In lesson 2, the worker may change report.py.

In your own project, inspect the proposed file list before approving it. Consider filtering, remote services, new dependencies and deployment as separate decisions.

Say how you will recognize success

Use concrete examples and a failure case. A polished appearance alone cannot establish that the totals are right.

  • Completeness: all six valid entries appear in the count, without a hidden filter.
  • Totals: the report shows 270 minutes; Orion 180 and Lumen 90.
  • Categories: Development 150, Documentation 75 and Testing 45.
  • Invalid input: an invalid row produces a helpful error and no misleading partial report.
  • Preservation: the input and protected checks remain unchanged.

Match each criterion to a check you can verify. You can add one total by hand now. In lesson 2, you will inspect the recorded test results.

Review the draft before you approve its scope. Authorize the build separately.

Which success criterion is useful before the reporting work starts?

The six supplied entries total 270 minutes, and project totals account for that same total. This is observable and can be checked independently from the source rows.

The report looks professional, so its totals can be assumed correct. Appearance can help the reader, but the totals still need independent checks against the input.
