Before you begin¶

Complete Get started in a fresh working directory. Keep the selected 1.5.1 validation environment active. R is the absolute preparation checkout at commit 7caa86ab6d476e9599b08ff75a81bc816e60c382; its example files are not in the wheel. These examples use a POSIX shell and canonical paths. On macOS, use /private/tmp instead of the /tmp symlink. Choose unused practice directories. Windows desktop and shell journeys remain unqualified.

Prepare the sample checkout¶

Use a disposable Git checkout with a deliberately incorrect add function. The following setup defines all variables before the planning commands use them:

P="$PWD/training-plan-project"
T="$PWD/training-plan-task"
PY="$(python -c 'import sys; print(sys.executable)')"
mkdir -p "$P/tests"
printf 'def add(a, b):\n    return a - b\n' > "$P/calc.py"
printf 'from calc import add\n\ndef test_add():\n    assert add(2, 2) == 4\n' > "$P/tests/test_calc.py"
git init "$P"
git -C "$P" add calc.py tests/test_calc.py
git -C "$P" commit -m "Training fixture"

P is the sample project; T is the unused task directory outside it. Do not put new files inside P after the next step freezes its inputs.

Preview and accept the plan¶

1. Create the request¶

attune-harness init --for plan --goal "Repair addition" --project "$P" --scope calc.py --interpreter "$PY" --tests tests/test_calc.py --task-dir "$T"

Expected: created; the request is written as $T.work.json beside the task directory.

2. Preview that request¶

attune-harness plan --request "$T.work.json" --project "$P" --config "$R/examples/starter/participants.json" --task-dir "$T"

Expected: draft with no missing questions. Inspect its goal, allowed file, effects and acceptance criteria. Set C to its full checkpoint_digest, for example C='the-full-returned-digest'; replace that literal with this preview's value.

3. If that exact scope is correct, accept its current checkpoint¶

attune-harness plan --task-dir "$T" --accept --checkpoint "$C"
attune-harness status "$T"

Expected result: Status is accepted. calc.py still contains a - b and there is no build run. Acceptance records the reviewed scope only.

Limit: This example stops before build. The starter reviewer approves without substantive judgment. A real build needs appropriate participants, frozen effects, protected checks and separately authorized execution. See Plan and build.
