## D1 — DynamicTeam docs are rewritten to AgentTeam, not deleted

The parallel-team capability still exists; only its implementation
changed (`DynamicTeam` → `attune.agents.team.AgentTeam`). Deleting the
docs would lose live, useful content. Canonical mapping for executors:

```python
# OLD (removed in #1096):
from attune.orchestration import DynamicTeam, DynamicTeamBuilder
builder = DynamicTeamBuilder(state_store=state_store)
team = builder.build_from_plan(plan)
result = await team.execute(input_data)

# NEW (live on origin/main; pattern lifted from
# src/attune/pipeline/orchestrator.py:245):
from attune.agents.team import AgentTeam, GateSpec, WorkflowAgent
from attune.workflows.code_review import CodeReviewWorkflow
from attune.workflows.security_audit import SecurityAuditWorkflow

team = AgentTeam(
    agents=[
        WorkflowAgent("code-review", CodeReviewWorkflow, files=files),
        WorkflowAgent("security-audit", SecurityAuditWorkflow, files=files),
    ],
    gates=[
        GateSpec("Code Quality", "code-review", 80.0),
        GateSpec("Security", "security-audit", 80.0),
    ],
)
report = await team.run(files)
# report.passed, report.blockers, report.warnings, report.results, report.cost
```

Note the semantic narrowing (D2 of the generic-agent-teams spec):
`AgentTeam` is **fan-out + gate only** — no DAG/sequential topology,
no `DynamicTeamBuilder.build_from_plan`. Docs that demoed builder/
strategy/plan-driven team construction must be trimmed to the fan-out
model, not faked onto the new API.

## D2 — MetaOrchestrator docs are deleted, not rewritten

`MetaOrchestrator` (NL meta-orchestration) was removed with no
successor. Per `removing-dead-code.md`, documenting a removed feature
is the failure mode, not a gap to refill. The two tutorials built
entirely on it (`META_ORCHESTRATION_TUTORIAL.md`,
`blog/interactive-agent-creation-tutorial.md`) are **deleted**;
scattered MetaOrchestrator mentions in surviving docs are **excised**
in place. The same-named class in `workflows/progressive` is NOT a
drop-in and must not be substituted to "save" the prose.

## D4 — Generated help is fixed at source, never hand-edited

`plugin/help/generated/**/orchestration.md` (+ the orphaned
`concepts/meta-orchestration.md`) are build artifacts. Their single
source is `content/features/orchestration.md` (projector model, per
the help-docs single-source rollout), expanded through

`scripts/generate_all.py`. Fix happens at the source + reprojection;
the generated diff is a product of the build. The orphaned
`meta-orchestration` generated concept (no source template dir) is
removed at the manifest/source layer so it stops regenerating.

## D6 — `integration/claude-code-integration.md` reclassified excise → DELETE (execution, 2026-06-26)

The `tasks.md` table classified this file **Excise** (10 meta refs, 0
surv, "keep the doc"). Execution verification contradicted that: the
**entire** doc documents `MetaOrchestrator.analyze_and_compose(
interactive=True)` — every code example instantiates the removed
`MetaOrchestrator`, and the IPC protocol / handler sections exist only
to serve that one dead path. There is no surviving-symbol content to
keep (the table's own `surv=0` confirms it), so "excise the dead
sections" would empty the doc.

The supporting primitive (`set_ask_user_question_handler`,
`AskUserQuestion`, `scripts/claude_code_ipc_monitor.py`) still imports,
but `git grep` shows **no live consumer** in `src/` other than its own
definition/docstring — its only consumer was the removed interactive
meta-orchestration. Writing a fresh doc for an orphaned primitive is
out of scope (requirements "Out of scope": no new orchestration prose
beyond removing/repointing dead symbols).

Per `.claude/rules/attune/removing-dead-code.md` (surfacing trip-wire:
making dead-feature docs coherent would require documenting orphaned
infra), the file is **deleted** and its `mkdocs.yml` nav entry pruned,
rather than excised. Inbound links exist only in append-only history
(`docs/specs/**`), excluded by D5. Follows the "spec-named scope drifts
from code reality — grep before executing" lesson.

it is **fiction from publication, not stale-but-once-true**: dated

call as `META_ORCHESTRATION_TUTORIAL.md`. Rendered on the website via
`website/lib/blog.ts`; the only inbound link was this decisions note.
