# Drift Guards → Generators — Requirements

**Status:** in progress (2026-06-12) — conversion 1 (version bump)
shipped; registration-mirror conversions open.
**Owner:** Patrick + agent
**Born:** discipline-review chat, 2026-06-11 (improvement #4 of 6).

## Problem

The repo protects against registry/manifest drift with
count-assertions and mirror tests. They work — drift is caught —
but each is a tax paid on every legitimate change:

- Adding a workflow: FOUR gates (`workflows/__init__.py` ×3 sites,
  `PATH_ARG_REGISTRY`, help-coverage `KNOWN_GAPS`/features.yaml,
  dashboard `WORKFLOW_NAMES` JS array).
- Adding a plugin skill: THREE gates (hardcoded count test,
  attune-hub Skills Reference table, `.agents/skills/` mirror).
- Version bump: 7+ files, two of which (`API_REFERENCE`,
  pyproject-vs-plugin-manifest) have already drifted silently for
  multiple releases because the guard didn't cover them.
- MCP tool counts, model-name strings, registry counts scattered
  across test assertions ("changing a shared string or count
  cascades — grep the whole test tree").

A guard that FAILS when you forget is strictly worse than a script
that DOES IT for you, when the derived artifact is mechanical. The
repo already proved the generator pattern works:
`scripts/sync_agents_skills.py` generates the mirror and a test
verifies sync — the test never fires because the generator runs.

## Outcome

For mechanical derived artifacts, one command regenerates everything
from a single source of truth; drift-guard tests remain only as
backstops that verify "the generator was run," and the per-change
friction drops to one edit + one command.

## Scope

Candidate conversions, by observed pain frequency:

1. **Version bump** — one `scripts/bump_version.py <version>` that
   writes pyproject + all plugin manifests + `plugin/core/__init__`
   + doc headers/footers, replacing the 7-file manual checklist.
   The `test_all_versions_match` guard extends to assert
   pyproject == manifests (the v7.2.0 drift class) and stays as the
   backstop.
2. **Workflow registration** — generate the dashboard
   `WORKFLOW_NAMES` JS array and the help-coverage list from the
   canonical Python registry at build/commit time; keep the
   `_DEFAULT_WORKFLOW_NAMES` triple-site as the single hand-edited
   source.
3. **Skill registration** — extend `sync_agents_skills.py` to also
   regenerate the attune-hub Skills Reference table and the count
   assertion's expected value.
4. **Count assertions generally** — where a test hardcodes
   `len(x) == N`, prefer asserting against the generated manifest
   or a structural property, so adding an item doesn't edit a test.

## Requirements

- **R1 — Single source of truth per artifact, named in the script
  docstring.** Every generator states what it reads and what it
  writes; generated files carry a "generated by X — do not hand
  edit" header where format allows.
- **R2 — Guards stay, inverted.** No protection is removed: each
  converted guard becomes "generated artifact matches a fresh
  generation" (the `test_skill_body_content_matches` shape). The
  failure message names the command to run.
- **R3 — Pre-commit wiring is optional and scoped.** Generators MAY
  hook pre-commit with tight `files:` filters, but the
  stash-and-reappear lesson applies — prefer "fail with the command
  name" over "mutate during commit" for anything beyond trivial
  output.
- **R4 — One conversion at a time, version-bump first.** It has the
  highest pain (every release), the clearest source of truth, and
  an existing drift incident (v7.2.0) as its regression fixture.
  Each conversion is one small PR.
- **R5 — Release-execute integration.** The release skill calls
  `bump_version.py` instead of narrating the 7-file checklist; the
  checklist text survives only as the generator's test expectations.

## Non-goals (this spec)

- Generating CHANGELOG content (judgment, stays human).
- Touching the `.help` regen pipeline (owned by polish-cost-reduction
  / attune-author; different failure modes).
- Converting guards whose value IS the judgment prompt (e.g.
  deprecation-marker past-due checks).

## Conversions shipped

| Guard | Generator | Backstop test |
|-------|-----------|---------------|
| Version-site drift (the v7.2.0 class) | `scripts/bump_version.py <version>` — writes all 7 files / 9 sites, count-validates before writing, verifies after | `test_plugin_config_validation.py::TestVersionConsistency::test_all_versions_match` (failure message names the command); plus `tests/unit/scripts/test_bump_version.py::TestRealRepo` (site list vs the actual tree) |

## Done when

- `bump_version.py` ships, release-execute uses it, and the next
  release's bump commit is generated (verifiable: one command, zero
  hand-edited version strings).
- At least one registration-mirror conversion (workflows JS array or
  skills table) ships with its inverted guard.
- A short table in this spec records each converted guard, its
  generator, and the backstop test.
