# Presenter notes: Turn an idea into a useful result

Derived from this lesson’s JSON.

## section-1: See where the work went

Six activity entries can answer a useful question: how much time went to each project and category?

- Show the useful report before explaining workflow terms. Ask the learner to locate one value they care about.
- Use the current supplied report and current checks summary. Opening an example is different from the learner completing a new task.

## section-2: Check the six entries

The projects and activity are synthetic. The small input makes the target result easy to check yourself.

- Let the learner work through one total in their own way. No arithmetic speed or coding skill is being assessed.
- Read the linked CSV if a displayed table and source disagree. Preserve the synthetic fixture.

## section-3: Describe what the person needs

State what the reader needs from the report. Let the assistant propose how to build it.

- Invite the learner to explain the goal without copying the lesson. Accept their wording rather than rewriting it silently.
- The prompt asks for preparation. Copying it does not create or accept a Harness task.

## section-4: Keep one complete useful journey

Agree on the report you will build and the files that may change.

- Ask whether an excluded feature is essential to this reader. If it is, revise the proposed first version before accepting scope.
- Avoid a file-by-file repository tour. The learner needs to understand the allowed effect and protected expected answers.

## section-5: Say how you will recognize success

Use concrete examples and a failure case. A polished appearance alone cannot establish that the totals are right.

- Treat the check as optional discussion. An incorrect choice must not lock navigation.
- Use the failure-case requirement to show that success includes an understandable problem path. No new tests are claimed here.

## section-6: Change the reader, then explain the consequence

Suppose a colleague only wants to compare the two projects. Does that require a new feature?

- Use less guidance here: ask the learner to distinguish interpreting the report from changing selection behavior.
- Preserve the learner’s wording. Browser notes are separate from the saved task and may be unavailable in another browser.

## section-7: Prepare a brief you can review

You are ready for planning when you can explain the goal, the boundary and what would establish success.

- Ask the learner to explain one scope boundary and one success criterion before following the next lesson.
- Keep version and observed-learning limits available without making them the main learning task.
