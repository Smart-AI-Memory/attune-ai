# Planning

## What

High-level development planning for new features, TDD scaffolding, and architecture review. Guides you through goal definition, scope decomposition, and dependency mapping — then produces a structured plan with tasks, acceptance criteria, and risk flags.

## Why

Jumping straight to code without a plan leads to rework. Planning forces you to think through edge cases, define done, and identify blockers before writing a single line — when changes are cheapest.

## When to Use

- Before starting a new feature or epic
- When designing a TDD approach for complex logic
- To review architecture decisions before committing
- When decomposing a large task into smaller deliverables

## What It Produces

| Output | Description |
|---|---|
| Feature spec | Goals, scope, non-goals, and constraints |
| Task breakdown | Ordered tasks with effort estimates |
| TDD scaffold | Test-first structure following red/green/refactor |
| Architecture review | Component diagram and coupling analysis |
| Risk assessment | Blockers, unknowns, and mitigation strategies |
