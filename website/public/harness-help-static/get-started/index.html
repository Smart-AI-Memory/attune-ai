Set up an isolated environment¶

Install published Harness 1.5.1 in a fresh environment. The release guide names its source, package files and Windows limits.

Use Python 3.10 or later. Keep Harness in its own environment: Harness and Attune-AI pin different MCP SDK versions. Attune-AI is not required.

  1. In a new working directory, create an environment: python3 -m venv .venv.
  2. Activate it. On macOS or Linux, use source .venv/bin/activate. On Windows PowerShell, use .venv\Scripts\Activate.ps1.
  3. Install the published release: python -m pip install "attune-harness==1.5.1".
  4. Check the selected interpreter's installed version: python -c "from importlib.metadata import version; print(version('attune-harness'))".
  5. Run the local demonstration: python -m attune_harness.

Expected result: The installed version is 1.5.1. The demonstration prints a JSON receipt with a verified result. It uses a deterministic local worker and an independent arithmetic check; it makes no model call. This result establishes that example's check, not the quality of an AI participant.

Prepare the release examples¶

The planning and research examples use files from the repository, which are not included in the installed wheel. With the published environment active, put the inspected source checkout in an unused directory:

git clone --no-checkout https://github.com/Smart-AI-Memory/attune-harness.git harness-release
git -C harness-release checkout ebb5b03b8a4398325df7ddabd28c08186451452e

Set R to that checkout's absolute path. In a macOS/Linux shell, from its parent directory, use R="$PWD/harness-release". The release commit is ebb5b03b8a4398325df7ddabd28c08186451452e. Verify it with git -C "$R" rev-parse HEAD. The tutorial setup uses POSIX shell syntax; Windows command adaptation is not newly tested here. Keep task records outside checkouts used for file effects. The PowerShell activation command is reference syntax, not a newly qualified Windows walkthrough. On macOS use canonical paths; /tmp is a symlink to /private/tmp.

Read dependencies and compatibility before adding optional providers or integrating with another host.
