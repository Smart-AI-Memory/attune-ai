Build a report you can explain

Turn six synthetic activity entries into an HTML report. Keep the input and tests unchanged.

Open the sample report. Look for 6 entries and 270 minutes, with 180 minutes for Orion and 90 for Lumen.

You will preview the work, approve its scope, run the local build and inspect the result. The practice worker supplies reference code. The local reviewer exercises the review protocol. The tests check the resulting program, and the practice makes no model calls.

For a project that needs more preparation, compare the goal-driven and spec-driven approaches.

Start in an isolated practice folder

Use the terminal and Python environment from course setup.

Complete course setup and keep the extracted folder open in the same terminal, with COURSE_WORK set.

Run the practice setup command below. It creates the sample project in $PRACTICE/project and writes the draft work request to $PRACTICE/task.work.json. Keep this terminal open for the rest of the lesson.

practice setup

PRACTICE="$COURSE_WORK/practice"
python practice.py "$PRACTICE"

Ask what may change and how it will be checked

Preview the request and check the proposed scope.

Run the plan command below. Look for draft, an empty list of missing questions and a checkpoint_digest.

Confirm that the goal and both test criteria match the exercise. The plan may change only report.py. It protects the CSV, expected reports, tests, participant registry and pytest configuration.

If the preview needs a correction, stop and revise the request through the supported workflow. Generate a fresh preview before you accept its scope.

plan preview

python -m attune_harness plan --request "$PRACTICE/task.work.json" \
  --project "$PRACTICE/project" --config "$PRACTICE/project/participants.json" \
  --task-dir "$PRACTICE/task"

Agree to the exact request

Accept the exact draft you reviewed. You authorize execution in the next step.

If the preview matches the exercise, replace the placeholder in PREVIEW_CHECKPOINT with the full checkpoint_digest from your preview. Run the command below.

Look for accepted and a new checkpoint. That records your approval of the reviewed scope. You are ready to decide whether to run the build.

scope acceptance

PREVIEW_CHECKPOINT="replace-with-your-full-preview-digest"
python -m attune_harness plan --task-dir "$PRACTICE/task" \
  --accept --checkpoint "$PREVIEW_CHECKPOINT"
What has acceptance established?

Agreement to the displayed scope; execution is still separate. The saved request is accepted. Starting the local command workers is the next decision.

The report has already been implemented and checked. Acceptance records intent, not implementation or test evidence.
