# Security-Audit Rich Output — requirements

**Status:** SUPERSEDED (2026-06-28) — the bespoke severity dashboard this
spec described was retired. Dogfooding showed security-audit emits
category-bullets, not the structured `Finding{severity,file,line}` shape
the dashboard assumed, so it rendered degraded on real output. Replaced
by the **universal `report_panel`** that renders any workflow's report
sections; see `docs/specs/analysis-workflow-output-widgets/` D4. Kept for
history.

**Owner:** Patrick + agent

The second consumer of the rich `show_widget` output pattern (after the
discovery-sweep triage board). security-audit is **output-only** —
`elicitation-form-surface` D12 ruled the path-scoped audit skills out of
input forms; the enhancement is a rich rendering of the findings.

## Grounding (verified against code)

- `security_audit` returns structured findings via the WorkflowReport:
  `attune.workflows.output.Finding` → `{severity, file, line, message,
  code}` (confirmed by `dataclasses.asdict`), plus a `health_score`.
  Not free-text — a dashboard is viable without LLM-prose parsing.
- The handler routes through the shared `_workflow_response` helper
  (unlike discovery-sweep's bespoke handler), exposing `findings` and
  `health_score` in the response dict.

## Functional requirements

- **FR-1.** The `security_audit` tool emits a `dashboard_html` field: a
  counts-by-severity header (chips + health score) over a
  severity-sorted findings list (severity badge, `file:line`, message,
  optional code). Pass to `mcp__visualize__show_widget`. Generated by a
  pure, injection-safe helper (`html.escape`, display-only — no
  `<script>`, CDS tokens, transparent bg).
- **FR-2.** security-audit skill Output: prefer the dashboard widget,
  markdown-table fallback.

## Non-goals

- No new MCP tool (would bump the 47-count guard / README / features.ts
  — same constraint as the discovery-sweep board). Extend the existing
  response.
- No change to the security-audit workflow or its finding model.

## Decisions

- **D1 — standalone now, unify later.** The severity palette + esc +
  location helpers overlap ~15 lines with
  `attune.workflows.discovery_sweep.board` (PR #1148, not yet on main).
  Rather than create a shared module with one live consumer while
  `board.py` is in-flight, the dashboard ships its own copy now; a
  single follow-up (once #1148 and this are both on main) extracts a
  shared `findings_widget` primitive and migrates both. Minor,
  tracked, transient duplication beats premature coupling.

## Acceptance

- `security_audit` response includes valid `dashboard_html`;
  `show_widget` renders severity chips + sorted finding cards; no raw
  finding text reaches executable JS.
- Helper unit-tested (counts, severity sort, missing location, code
  present/absent, injection escaped, no `<script>`).
